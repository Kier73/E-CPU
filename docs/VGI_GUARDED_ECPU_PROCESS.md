# E-CPU process execution of certified VGI Grounds

## Capability

E-CPU executes the *actual installed* Virtual-Ground-Interpreter guarded-process implementation as an admitted local M2 computational artifact, using the existing HeadlessOS process scheduler, Hypervisor capability decisions, typed Virtual Layer operator registry, and M2 host receipts. The workload supplies mathematical Grounds and observations, not executable code.

The external source revision is `Kier73/Virtual-Ground-Interpreter@39a169b21513ffaaee85e40826c706c07a47215b`. Two dependency modules have exact SHA-256 pins checked by the receiver. M2 admits the entire installed `vgi` Python package as a source artifact; the backend profile binds its manifest, protocol and runtime version.

## Actual execution route

`Python child process → HeadlessOS native VM program → local capability-bearing kernel service → VirtualLayerWorkload → Hypervisor authorization → M2 LocalComputationalHost → pinned VGI mathematical kernel → E-CPU M2 receipt + VGI verification receipt`.

The receiver supports three typed pure operations:

| Operation | Inputs | Result |
|---|---|---|
| `guarded.advance` | Source Ground, VGI certificate, projected state, up to 512 input symbols | Verified transition receipt, final state, observation |
| `guarded.migrate` | Old/new Grounds and certificates, verified prior execution receipt, additional probe values | New projected state, exact probe demand, explicit caller-probe status |
| `guarded.jump` | Source Ground, certificate, quotient state, input symbol, decimal step count | Invariant-branch affine exponentiation and resulting state |

No arbitrary Python source is evaluated. The E-CPU host validates the locally installed interpreter byte identity before binding it. VGI independently checks every algebraic transition/certificate, and receipts are recomputed and verified.

## Reproduce with Python

With E-CPU and Virtual-Ground-Interpreter checked out:

```sh
python -m pip install -e . pytest
python -m pip install -e ../Virtual-Ground-Interpreter/virtual_ground_interpreter
python -m pytest -q tests/test_vgi_guarded_runtime_host.py
```

Use the exact pinned VGI commit; admission refuses changes in the two pinned mathematical modules.

The data-only one-shot worker is `python -m mailcpu.vgi_guarded_worker`, accepting one bounded JSON object on stdin. Its request envelope is:

```json
{
  "schema": "mailcpu.vgi-guarded-worker.v1",
  "workload_id": "demo-001",
  "logical_time": 1,
  "request": {
    "operation": "guarded.advance",
    "input": {
      "source": "<complete GuardedGround.to_dict()>",
      "certificate": "<complete discover_guarded_reduction() result>",
      "initial": [0, 1],
      "inputs": ["tick", "tick"]
    }
  }
}
```

The strings denoting source and certificate above are placeholders showing the envelope; supply the actual JSON objects generated by VGI. The integration test constructs these valid payloads and drives real child processes.

The dedicated workflow `.github/workflows/vgi-guarded-ecpu-process.yml` obtains the external VGI revision using a commit-pinned `actions/checkout` and runs these tests.

## Exact authority and proof boundaries

* VGI proves equivalence for declared guarded finite-field affine systems under the certified observation projection. The test uses a 2^80-state source with a 4-state exact quotient, then upgrades to an 8-state quotient with one additional probe.
* E-CPU M2 receipts bind the source artifact, backend profile, local host, request and result. Their `EXECUTED` status is **not** a signed remote statement or durable M3 commit.
* Independent one-shot OS processes are exercised by the tests; the resulting process continuation is **receipt-carried**, not yet a durable CAS-backed E-CPU session.
* Migration inputs include caller-provided probe values. The lift is algebraically correct **if the probes are authentic**; this release intentionally labels them `CALLER_SUPPLIED_NOT_ATTESTED`. A future E-CPU session should bind them to a source checkpoint and recovery-lineage epoch.
* The worker grants compute capability to a receiver-owned internal service. It never trusts an incoming sender to grant that permission.
* Limits: ≤128-dimensional finite-field source, certificate and input byte ceilings, at most 512 actions per step quantum, and bounded integer size for jump commands.
