# HFG-002 — Verified pretrained Transformer layer through E-CPU Grounds

**Status:** runnable numerical integration and pinned live-Hub CI experiment. Local synthetic math: passed. Real Hugging Face range acquisition / native receiver: to be established by hosted GitHub Actions; do **not** infer success from this document or from HFG-001 architecture-only descriptors.

## Research question

Can E-CPU treat a complete modern Transformer layer as a *Ground-directed observation*, retrieving actual trained parameter bytes from a pinned model and realizing the layer through existing authorized E-CPU operations, rather than constructing another model-specific operating system?

- **Numerical checkpoint:** `Qwen/Qwen3-0.6B` at immutable revision `167b8104f88905a951069f5f95f9776908da5f68`; Apache-2.0. [Pinned config](https://huggingface.co/Qwen/Qwen3-0.6B/blob/167b8104f88905a951069f5f95f9776908da5f68/config.json).
- **Independent neural-structure reader:** `Kier73/In-Formation-Space` commit `c9716242725be65937fda1dd7b6cb778ca1def91`, module `experiments/external_neural_structure_reading/hub.py` (HFR-001).
- **E-CPU**: HFG-001 `HFModelGround`, MWS-001 exact `ModelWeightSnapshot`, `ComputationalObjectStore`, existing `VirtualLayerRuntime` / Hypervisor and `NavigableComputationDAG`.
- **Mathematical reference:** separate PyTorch implementation of a Qwen3 dense decoder layer, explicitly evaluating **FP32 arithmetic on BF16-decoded pretrained weights**. This is not a BF16 bit-exact reproduction of an optimized GPU inference kernel.

The model Ground is the *full model's pinned architecture and header observation*. MWS-001 holds an exact **subset** snapshot for the eleven tensors of layer zero. The subset is NOT mislabeled a fully verified 0.6B checkpoint. The live workflow retains actual selected tensor content SHA-256s and headers, not raw tensor bytes.

Qwen3-0.6B is selected because its real layer weights fit HFR's already implemented ≤16 MiB/tensor, ≤64 MiB/selection bounded-range acquisition policy. The **semantic and addressing architecture is not capped by this model size**: HFG-001 continues to describe Qwen3-235B layer frontiers; the numerical test grows to 30B/235B by adding qualified sparse MoE and distributed weight paths.

## Executable sequence

1. `IFS HFR.inspect_huggingface_model()` observes the immutable source config, weight inventory, shard headers and offsets (no payload bytes).
2. `HFG-001 HFModelGround.from_nsd()` refuses inconsistency, binds the architecture, model revision, 11 expected layer tensor shapes and ordered semantic dependencies.
3. `IFS HFR.fetch_selected_tensor_payloads()` explicitly allowlists exactly eleven first-layer tensors and rechecks source/shard headers before bounded range reads.
4. `MWS-001 ModelWeightSnapshot.publish_tensors()` stores and verifies actual bytes in E-CPU `ComputationalObjectStore` using its existing `PageBacking` interface; each tensor's source coordinates and fetched content digest are retained. MWS-002 generative recipes are eligible alternatives when they reconstruct **the same exact tensor bytes**, not substitutes for missing data.
5. E-CPU native receiver creates an authorized `HeadlessOS`, admitted `SystemSeedEnvelope`, `VirtualGroundRef` and two `OperatorSpec`s on a single `VirtualLayerRuntime`.
6. `NavigableComputationDAG` first commits the stated hidden input digest; *attention* is authorized and executed, then the dependent *MLP* node becomes ready and executes. No separate scheduler or model authority is introduced.
7. Attention stage: RMSNorm → pretrained Q/K/V projection → per-head Q/K normalization → RoPE → grouped KV and causal attention → pretrained output projection → residual.
8. MLP stage: post-attention RMSNorm → pretrained gate/up → SiLU × up → pretrained down → residual.
9. Compare the complete layer result to an independently implemented PyTorch reference, with a declared numerical tolerance, source/snapshot/output hashes and per-operation authorization receipts.

This is a **full layer** at a reproducible known input, **not full model inference**. The input is an explicit deterministic two-token hidden vector, not an embedding generated by executing preceding model layers. KV cache is built for the query only; long-lived prefill/decode and tokenizer state are not established. NumPy/CPU is the current numeric *realizer* under E-CPU's Hypervisor, not the definition of the Ground or proof of path-native arithmetic.
