# INTERNET-009 — The Internet revises the computational Ground it is navigating

**Status:** new E-CPU experimental composition of INTERNET-004/005/006/007/008, original `HeadlessOS`, original `EvidencePathResolver`, E-CPU `FiniteGround` sufficiency and optional VGI attention. Native cross-platform and public-Internet observation gates are authoritative for their respective claims; implementation alone is not live evidence.

## Throughline

The E-CPU proposition **“the internet is the computer”** becomes operational when protocol and document relations are treated as source-qualified mathematical operations, rather than messages carrying ordinary CPU instructions. The existing system already has several concrete building blocks:

- INTERNET-001–003: Git object/ref relationships and HTTP validator/cache state as existing service-specific relations.
- INTERNET-004: bounded real RFC Editor HTTPS reference navigation, preserving original raw HTML and independently reconstructing its link graph without a new network fetch.
- INTERNET-005: exact observer cases compiled into native `EvidencePathCatalogue`, resolved under current `HeadlessOS` authority and typed cost metrics.
- INTERNET-006: receiver-approved *prospective* probes; the native receiver owns source-specific verifiers and the executable handlers.
- INTERNET-007: multi-gap attention over hypothetical possible route completions, without mistaking them for verified edges.
- INTERNET-008: real VGI three-valued distinguishability and E-CPU finite intention sufficiency to choose a first eligible probe. The counterfactual model does **not** come from the website or grant an observation capability.

The most useful gap left by these systems was a feedback relation:

> Once the network has actually supplied an independently checked observation, how does the intention's mathematical *possibility space* update, with its old Ground preserved and the next observation chosen from the reduced space?

INTERNET-009 contributes this missing layer. It is not a new crawler, router, TLS library, HTTP stack, consensus service, full CPU, optical computer or shadow native executor.

## The evidence-to-Ground transition

Let `G0` be a finite receiver-supplied hypothesis table, `H0` its content identity and `C` the exact Ground/context/intention contracts. The table contains states with a public projection, a finite list of potentially measurable features, and a target interpretation.

For a feature `f` and an **actually source-qualified reading** `v`, the retained candidate set is

[
S_{n+1} = \{s\in S_n:\operatorname{feature}_f(s)=v\}.
]

The previous Ground remains unchanged. A new E-CPU `FiniteGround` is reconstructed only if `S_{n+1}` is nonempty. If all possible states disagree with the observation, the observed evidence is **not discarded or converted into a negative response**: the revision is recorded as `MODEL_CONTRADICTION` and no intention result is returned until the hypothetical model is independently rebuilt.

The source observation is admitted **only if all of the following hold**:

1. The original native `ProspectiveQualifier` has actually dispatched a receiver-installed handler and recorded a successful, append-only `ProbeEvent`; a hypothetical `ProbeOffer` or VGI `ProbeScenario` cannot satisfy this.
2. The exact event belongs to the original native attempt chain, binds an offer that was present in the receiver registry and a case that entered the original `InternetGroundRouter`, and its source, target, kind, Ground, context, provider and source lease match the intention.
3. The receiver re-invokes the original provider-specific verifier and native `InternetGroundRouter._edge` observation comparison. A self-hashed response cannot bypass those contracts.
4. A **separately receiver-installed bounded decoder**, not retrieved or chosen by the website, rechecks the **original raw source archive** and independently derives a typed feature value plus exact source-capture and native case-evidence digests. If either digest disagrees with the admitted native event, no revision occurs.
5. The observation's feature belongs to the original receiver-provisioned measurement catalogue. Source bytes never insert arbitrary features, new capabilities, operations, handlers, model states or authority.
6. One append-only revision receipt records the original base Ground hash, original live HeadlessOS authority digest, offer/case/attempt identities, raw archive digest, exact reading, before/after state IDs and previous revision digest.

After each admitted reading, INTERNET-009 runs **the original exact `plan_sufficiency` on the surviving states**, using the not-yet-observed receiver-approved feature catalogue. If the target is unique under that model, it returns `CONDITIONALLY_RESOLVED`; otherwise it identifies which admissible features still have value. If no catalogue can distinguish remaining target interpretations, the status is `MODEL_UNRESOLVED`, not an invented answer.

The target is **conditional on the completeness and correctness of the receiver's original finite model**; even a fully verified HTTP source cannot prove that an arbitrary hypothetical model spans the real world. `CONDITIONALLY_RESOLVED` is not a native route completion or external effect permission. The original Internet Ground routing and Hypervisor retain their own authority.

## Native E-CPU/VGI controlled probe

The actual INTERNET-008 fixture contains two alternatives from a source: DNS with two possible future Git suffixes, and HTTP with one RFC suffix. INTERNET-007's structural coverage prefers DNS; actual VGI distinguishability and E-CPU exact target sufficiency prefer HTTP. The receiver initially has four finite hypothesis states and requires the HTTP feature to determine the modeled target.

INTERNET-009 takes the **actual original** E-CPU/VGI-selected and native-admitted HTTP case and an independently receiver-checked (explicitly synthetic) raw observation, then:

- reduces four candidate finite states to the two consistent with the observed HTTP feature;
- recomputes exact sufficiency, determining a unique **model-relative** target with no need for another feature;
- preserves the original Ground and its four states for independent replay;
- **does not** claim that the native multi-hop Internet route completed: the test's first HTTP case can be admitted while its subsequent RFC route segment remains unobserved;
- distinguishes a failed probe (`probe_refused`) from a valid measurement that contradicts the finite model (`MODEL_CONTRADICTION`).

Negative tests reject altered source bytes (including self-rehashed labels), forged or detached event receipts, changed case verifier, invalid source lease or intention context, false raw/source digests, altered attempt chain and forbidden model features.

The synthetic fixture is explicitly **not** reported as a live public Internet observation. It is a controlled mathematical and native authority regression.

## Public Internet experiment: existing RFC Editor as a computational observer

The new script [`examples/revise_public_internet_ground.py`](../examples/revise_public_internet_ground.py) uses the original INTERNET-006 `setup` to pin a receiver intention `RFC 9293 -> RFC 793`, an allowlisted exact `www.rfc-editor.org` HTTPS source, strict limits (four pages, two link levels, 1 MiB observed response bytes, no redirects), and a native HeadlessOS `observe` capability.

On the live GitHub Actions runner it:

1. Uses original INTERNET-004 `navigate` to fetch raw HTML and reconstruct the RFC reference path. The remote RFC service is the observed information space, **not** a worker running E-CPU.
2. Uses original INTERNET-005 `admitted_rfc_observation` for exact native `InternetObservationCase` and original INTERNET-006 `ProspectiveQualifier.step` to admit its verified route under the explicit receiver capabilities.
3. Independently parses the entire retained raw capsule through the receiver-installed INTERNET-009 feature decoder, rerunning `verify_capsule` against the original actual page bytes, media type, link graph and exact path and comparing all capture/case digests.
4. Refines the original two-state finite model (`path_observed=True/False`) to one state using the observed evidence, recomputes exact E-CPU sufficiency and emits a versioned source-conditioned receipt.
5. Reconstructs the same model and receipt with a fresh independent local reader over the original native case and raw archive. A **separate GitHub Actions job on another runner** additionally downloads the live artifact and performs the full original E-CPU case admission and INTERNET-009 Ground revision from archived bytes without making another Internet request.

The public result is an **observed reference-path computation**, conditional on the actual current RFC source and the declared two-state model. It is not evidence that passive fiber performed arithmetic or that the RFC service ran arbitrary code. Only source-side TLS is used; neither the RFC HTML, the capsule nor its SHA-256 is an independently authenticated publisher signature. The source SHA is pinned by the receiver *after* collecting its first real observation, not independently known before network access; the report states this explicitly.

The offline replay may verify bytes and the claimed link relation but **cannot independently attest that those exact bytes originated at the purported remote server**. The network access and the later replay have different evidence grades.

## Distinguishing measurements

This milestone logs each original native probe count and request count, raw observed bytes, source event and case hashes, exact candidate-state elimination, change in selected sufficiency requirements, and replay equality. The public experiment should compare against an exhaustive browser that fetches additional pages only where its own declared intention requires them; it must not attribute a source-document reference lookup to a physical or hardware speedup.

No network route, source, or resource becomes a future arbitrary execution opportunity merely because the model was refined. Safe failure is `MODEL_UNRESOLVED` or `MODEL_CONTRADICTED` without a fabricated result.

## Reproduction

```sh
export PYTHONPATH="$PWD/vgi-source/virtual_ground_interpreter:$PWD/tests"
python -m unittest discover -s tests -p 'test_internet_observed_ground_revision.py' -v
python -m unittest discover -s tests -p 'test_internet_distinguishability_attention.py' -v

python examples/revise_public_internet_ground.py observe \
  --seed 9293 --target 793 --output /tmp/internet009-live.json

python examples/revise_public_internet_ground.py replay \
  --seed 9293 --target 793 \
  --input /tmp/internet009-live.json \
  --output /tmp/internet009-offline.json
```

The dedicated workflow checks out the exact VGI `7a3c4a368d1d24044a6c06a317c26ef316513e6d` and tests E-CPU's native Internet suite on Python 3.11 and 3.13. The live HTTPS and independent offline replay run **in separate jobs** with a short-retention artifact, no credentials or private keys.
